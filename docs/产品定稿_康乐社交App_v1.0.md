# 康乐社交 App 开发规格 v1.0

- 日期：2026-10-06
- 基线：《需求文档_康乐社交App_v0.4_赛道2》
- 平台：iPhone（iOS 原生）
- 原型截止：2026-10-18
- 标注：**【待定】** 表示还没有共识，括号里是默认值，开发先按默认值做

---

## 1. 产品是什么

北都新入伙屋邨的居民，散步时被 App 自动记录。同一片区域常走的人，会出现在同一张社区排行榜上。两人见面时手机相碰，就成为"街坊"。成为街坊之后，可以收到对方的出门提醒、用语音约对方一起散步，约定当天由 App 引导两人碰头。

用户：北都新屋邨的新居民，不限年龄。所有功能遵循包容性设计，老年人也能用。

---

## 2. 范围

### 本版做

F1–F10，见第 3 节。

### 本版不做

- 站内聊天、转发
- 通用问答、健康建议

V0.1 里的团课、积分、建议投票、通用 AI Bot 不管。

## 3. 功能规格

### F1 自动记录散步

- 检测到步行时自动开始记录，停止步行后自动结束，用户不需要操作。
- 用 Core Motion 检测步行状态，只在步行时开启定位。
- 进入"家附近"范围后停止记录，并且不再对外显示位置。
- 一次散步生成一条**散步记录**和若干个**落脚点**。
- 落脚点的定义：在同一位置附近停留 ≥ 【待定】（2 分钟）、半径 ≤ 【待定】（30 米）。
- 原始轨迹只保存在手机上，上传到服务器的只有落脚点对应的地标。
- 验收：用户全程不碰手机，一次散步被完整记录。

### F2 划圈

- 一周内有 ≥ 3 个落脚点重合的用户，归入同一个圈。
- 一个屋邨可以有多个圈，一个人可以属于多个圈。
- 刚入伙、数据不够时，先按同一座楼分圈。
- 原型阶段使用预设的分组。

### F3 地标命名（AI）

- 输入落脚点的坐标和附近设施，输出居民会用的叫法，例如"7 座后面有凳嗰度"。
- 用户可以用语音给地标改名，改名对同圈的所有用户生效。
- 产品内所有位置一律显示为"地标名 + 附近"，不显示坐标和地图。

### F4 社区排行榜

- 一个圈一张排行榜，显示名次。
- 排名依据：【待定】（连续散步天数）。
- 每个成员显示为：卡通小人 + 座数和楼层 + 一句 AI 生成的当天描述（如"12 楼今日行到河畔"）。
- 非街坊之间不显示姓名、照片和门牌。
- 用户可以用语音请假，请假期间连续天数保留。
- 圈与圈按月比拼圈内总步数，月末公布胜出的圈，胜出圈的成员获得一个卡通标记。

### F5 碰一碰

- 两部手机距离 ≤ 【待定】（10 厘米）时，判定为一次"碰"，双方成为街坊。
- 只能这样添加街坊；不提供搜索、远程邀请和邀请链接。
- 配对成功后，双方手机都要有语音确认。
- 任一方可以随时解除街坊关系，对方不会收到通知。
- 技术方案：Nearby Interaction（超宽带）。配对凭证通过 MultipeerConnectivity 交换。
- 限制：两部都要是 iPhone 11 及之后的机型（SE 不支持），App 必须在前台。
- 备选：扫二维码添加，给不支持的机型用，也作演示现场的兜底。
- 验收：两部手机在 2 秒内完成配对。

### F6 出门提醒

- 街坊开始散步时，用户收到一句提醒，例如"12 楼陈太刚出门，应该在河畔那边"。
- 默认双向开启；每次成为街坊时，询问双方是否开启。
- 用户可以单独关闭"发送"或"接收"，也可以只在指定时段接收。
- 验收：街坊出门后 2 分钟内收到提醒；提醒内容里有地标，没有坐标。

### F7 语音约人（AI）

- 用户说一句话发起约会，例如"约陈太明天一起行"。只能约街坊。
- AI 解析出约会对象和时间。
- AI 自动选地点，条件：双方都常经过、离双方都近、有座位，优先选约定时段有遮荫的地点。
- 对方只需一次确认就能接受；接受后，双方各收到一句完整的口头约定。
- 用户可以用语音修改时间或地点，也可以点按钮修改。
- 验收：从说出请求到对方收到，中间不出现任何其他界面；AI 能用一句话说明选这个地点的理由。

### F8 当天找人

- 对方出门时通知用户，并估算对方的到达时间。
- 双方距离 ≤ 50 米时手机震动；进入超宽带的测距范围后，显示大箭头和地标图标指向对方，不显示地图。
- 用户说一句"我在凉亭"，就能播送给对方。
- 超过约定时间 10 分钟仍未碰头，AI 询问是否拨打电话。

### F9 天气与遮荫提示（AI）

- 根据天气预报、遮荫数据和用户的出门习惯，在前一晚或当天出门前，建议提前、推迟或取消散步，并推荐有遮荫的路线。
- 散步中，如果步频明显下降，提示休息并告知最近的座位。
- 每次提示不超过一句话；用户不回应，就不重复提示。

### F10 北都月报（AI）

- 散步中用户可以说一句反映，例如"呢度好晒""呢度冇凳"，AI 把它挂到最近的地标上。
- 每月用全邨的匿名散步数据加居民反映，生成一份月报，交给社工、屋邨管理和新发展区团队。
- 月报内容：多人走过却没有遮荫的路段、常停下却没有座位的地点、因施工绕路的位置、自发形成的聚脚点。
- 只输出地标级、且人数 ≥ 【待定】（10 人）的汇总，不输出任何个人轨迹。
- 这是独立模块：拿掉 F10，F1–F9 不受影响。

## 4. 通用要求

- 以语音和图像为主，不做多级菜单；每个语音操作都要有一个大按钮作后备。
- 最小字号 24pt，可调；配色要通过色弱安全检查。
- 卡通形象要覆盖轮椅、拐杖、婴儿车、不同年龄和肤色。
- 所有提示同时有语音和图像。
- 支持粤语和普通话。
- 首次使用时，用语音说明"谁能看到什么"，完成知情同意。

## 6. 分工

### 成员 A

- App 骨架：导航、设计规范、登录、知情同意
- 后端和全部数据表
- 所有界面和视觉，包括 B 负责的功能的界面，以及碰一碰的画面和动画
- F1、F2、F4（排名、请假、比拼）、F6、F8
- 遮荫计算

### 成员 B

- 语音识别和播报的封装
- F3、F4 的每日一句、F7、F9、F10
- 语音指令：请假、改名
- F5 的配对和语音确认逻辑

### 规则

- B 不写界面。B 的产出是第 8 节列出的接口，A 的界面调用这些接口。
- A 先用假数据把界面全部做完；B 每完成一个接口，就替换掉对应的假数据。
- 接口一旦定下，要修改必须双方同意。

## 7. 数据表（初稿，第 1 天两人一起确认）

| 表 | 主要字段 |
|---|---|
| 用户 users | id, 昵称, 座数, 楼层, 卡通形象, 家附近范围, 语言, 创建时间 |
| 地标 landmarks | id, 名称, 坐标, 有无座位, 屋邨, 圈 id |
| 圈 circles | id, 名称, 屋邨 |
| 圈成员 circle_members | 圈 id, 用户 id |
| 街坊关系 neighbors | 用户 1, 用户 2, 建立时间, 用户 1 发送提醒, 用户 1 接收提醒, 用户 2 发送提醒, 用户 2 接收提醒 |
| 散步记录 walks | id, 用户 id, 开始时间, 结束时间, 步数, 经过的地标 id 列表, 当天一句话 |
| 请假 leaves | 用户 id, 开始日期, 结束日期 |
| 约会 meetups | id, 发起人, 对象, 时间, 地标 id, 选点理由, 状态（待确认 / 已接受 / 已完成 / 已取消） |
| 居民反映 reports | id, 用户 id, 地标 id, 原话文字, 分类, 时间 |

## 8. 接口

### A 提供，B 调用

| 接口 | 输入 | 输出 |
|---|---|---|
| `getShade(landmarkId, timeRange)` | 地标、时段 | 遮荫比例 0–1 |
| `createNeighbor(userA, userB)` | 两个用户 id | 成功 / 失败 |

### B 提供，A 调用

| 接口 | 输入 | 输出 |
|---|---|---|
| `parseVoice(audio)` | 录音 | `{intent: 约人 / 请假 / 改名 / 反映, params}` |
| `dailyLine(walk)` | 一条散步记录 | 一句话 |
| `nameLandmark(coord, facilities)` | 坐标、附近设施 | 地标名 |
| `pickMeetupSpot(userA, userB, time)` | 两个用户、时间 | `{landmarkId, reason}` |
| `walkAdvice(userId, date)` | 用户、日期 | 一句提示，或 null |
| `monthlyReport(estateId, month)` | 屋邨、月份 | 月报内容 |
| `speak(text)` | 文字 | 播放语音 |

每个接口的输入输出示例，第 1 天补齐。
