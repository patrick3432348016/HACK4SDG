# Prototype Status: Implemented, Simulated and Unverified

> Historical implementation notes, mainly from 8–11 October 2026. Later additions were recorded unevenly, so some rows contradict one another. They are preserved as dated evidence, not a current acceptance checklist. Use the [current README](../README.md) and code for today's implementation. Current main includes three languages, Doubao and real live finding; old statements about template-only AI, missing English or simulated device finding are superseded.

This document supports the official **Prototype/demo (20%)** category by distinguishing working components from simulation. Static code, team-reported tests and independent device observations are different kinds of evidence.

At the time, a single iPhone implemented map generation, a 3D scene, landmarks, estimated building shade, routing, HKO weather, template intent parsing, local persistence, meetings, device walk detection, home learning and local notifications. With Always location permission, iOS could wake the App after home departure and continue recording while locked. Without that permission, or after a user force-quit, foreground return used Core Motion history to backfill minutes and steps.

A 10 October addition connected normal mode to Supabase: nearby real accounts, paired-neighbor outings, finding requests, invitations, rescheduling, cancellation and messages. The team reported two-simulator end-to-end checks. Pairing used `link_neighbor`; demo mode retained simulated neighbors. The original notes also described completed UWB/QR work while older rows still assigned UWB integration to B.

The Demo label and menu identify sample residents, responses, management replies, manually selected weather, leaderboard/report values and simulated finding. Disabling demo switches to real backend data; an otherwise empty community may then contain only the current user.

## Verification entry points

- `ios/tools/test.sh`: Xcode tests for map/shade/routing, intent and voice flows, finding, streak/leave, persistence/migration, demo separation, report threshold, stops, device start/end logic, motion backfill, cadence, notifications, color/appearance, backend mapping/outbox, home learning and pairing. Use the latest actual run for counts. Failures return nonzero. Override simulator with `SIM="iPhone 17 Pro Max" ./tools/test.sh`.
- `ios/tools/backendtest.sh`: **live Supabase integration**, historically 19 checks, creating two anonymous users and printing IDs. It is not an offline check; run only with an authorized test target and cleanup plan.
- Two-simulator backend flow: launch both at the same estate with `-demoMode NO -resetData -resetOnboarding -resetBackendSession -scriptOnboarding -debugNickname <name> -debugCommands`. Write `link <same-code>`, `remind on`, `walk`, `find <name>`, `answer yes`, `invite <name> 1 16`, `accept`, `depart`, `unlink <name>` or `bgrefresh` to the App container's `Documents/debug-commands.txt`. Inspect `debug-state.txt` and `debug-events.txt`; see `Store/AppStore+DebugCommands.swift`.
- `ios/tools/selftest.sh`: core checks without a simulator.
- `tools/voice_server.sh` starts voice services; `--test` historically ran 60 checks (41 B, 9 Supabase adapter, 10 speech). Counts are historical, not current pass evidence. `python3 server/tools/tts_probe.py "Hello"` measures first-audio timing. Debug commands include `voice`, `vchip`, `vpick`, `vok`, `vno`, `vcheck` and `speak`; state/events expose server/card state, route and first-audio timing. See [server guide](../server/README.md).
- `ios/tools/run.sh -demo -skipOnboarding -script` runs the roughly 95-second recording flow. `-script2` and `-script3` cover Neighbors, cards, rescheduling, reports, reminders, expiry, unlinking and Settings.
